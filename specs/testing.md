## Как проверить Windows на настроенном сервере

Чистый прогон с Windows на настроенном сервере невозможен: пароль root уже отключён. Поэтому Windows проверяется как второй компьютер со своим ключом, по README, раздел «Второй компьютер». Приватный ключ с первого компьютера не копируется.

- Подготовка: VS Code на Windows, `ssh -V` в PowerShell отвечает
- Команда - из `README.md` этой папки, «Запуск версии до релиза», с `-ServerHost <IP>` в конце
- Шаги:
  1. Первый запуск в Windows PowerShell 5.1: ключ создан без passphrase, затем остановка `This server is already set up with another key` с путём к `.pub`
  2. Публичный ключ `%USERPROFILE%\.ssh\vprod_ed25519.pub` добавить на сервер с первого компьютера: `echo '<ключ>' | ssh vprod 'cat >> ~/.ssh/authorized_keys'`
  3. Второй запуск: без пароля root, `Everything is already set up.` (A5), запись `~/.ssh/config`, Remote-SSH, рабочий стол
  4. `ssh vprod` из PowerShell входит без пароля
  5. Действия `-Action check`, `-Action desktop`, `-Action login`
  6. VS Code → Remote Explorer → `vprod` → Connect, `claude` в терминале VS Code работает без повторного входа

## Осталось проверить

Без переустановки сервера:
- PowerShell 7 (`pwsh`): повторный запуск, `check`, `login`. После проверки вернуть PowerShell 7 в README и в `requirements.md`, раздел 1
- Правки после теста на Windows на реальном сервере:
  - запуск с `VPROD_SSH_ALIAS=vprodtest` останавливается с подсказкой для второго компьютера и путём к ключу; затем удалить `~/.ssh/vprodtest_ed25519*`;
  - повторный запуск и действие `desktop` пишут `Claude Code is already logged in.`, а `login` - шаги входа
- A12, A13, A18: свой `Host *` и чужой `Host vprod` в `~/.ssh/config`, 6 и больше ключей в ssh-agent, `~/.ssh/config` - симлинк
- A14: пользователь Windows с кириллицей и пробелом в имени
- A16: `setup.sh` в WSL, IPv6-адрес в `VPROD_HOST`
- A22: повторный запуск `github.sh`

Нужен новый или переустановленный сервер:
- A2, A4: чистая установка с Windows, с вводом пароля root, в PowerShell 5.1 и 7
- Ubuntu 26.04: чистая установка (как A1) и проверки из 11.2. После проверки вернуть 26.04 в README и в `requirements.md`, раздел 1
- A6, A7 на реальном сервере: обрыв сети и Ctrl+C во время `prepare`
- A8: смена ключа хоста после переустановки (проверится сама при первой переустановке)
- A10: сервер с 2 ГБ и с 1 ГБ памяти
- A20: сбой `prepare` после создания пользователя и повторный запуск

## Две программы PowerShell

- `powershell.exe` - Windows PowerShell 5.1, встроен в Windows, развивается только исправлениями
- `pwsh` - PowerShell 7, отдельная кроссплатформенная программа для Windows, macOS и Linux. На Windows ставится рядом с 5.1, не заменяя его
- На Маке `pwsh` нужен только для статических проверок `setup.ps1` (PSScriptAnalyzer, разбор синтаксиса). Поведение 5.1 на нём не проверить, это делается на Windows
