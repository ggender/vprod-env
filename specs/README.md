# Разработка установщика

Эта папка нужна, когда меняют и проверяют сами скрипты установщика. Чтобы поставить среду, она не нужна: хватает [README](../README.md) в корне.

## Файлы

- [`requirements.md`](requirements.md) - требования к установщику: сводка для проверки автором и детали для агента. Источник истины для кода
- [`testing.md`](testing.md) - что проверено, как проверять Windows, что осталось проверить
- `README.md` - этот файл: как вести разработку

Скрипты лежат в корне репозитория, а не здесь. Клиент скачивает их по адресу `<BASE_URL>/<файл>`, поэтому переносить их нельзя.

## Требования

- Код пишется по `requirements.md` и по официальной документации Ubuntu, OpenSSH, VS Code, Anthropic, Mozilla, noVNC. Сторонние установщики подобных сред не открывать и не брать за образец
- Назначение файлов - `requirements.md`, раздел 2
- Изменились команды, действия или файлы - обновить README в корне

## Язык

- Код, комментарии, лог сервера и все сообщения ученику - на английском, по правилам `requirements.md`, раздел 2: уровень A2, ошибка = что случилось + что сделать
- Сообщения коммитов - на английском
- README, `AGENTS.md`, документы в `specs/` - на русском

## Совместимость

Детали - `requirements.md`, разделы 8.1 и 8.2. Главное:

- `setup.sh` работает в bash 3.2 (системный в macOS): без ассоциативных массивов, `mapfile`, `${var,,}`, `local -n`, без `python3` и `sed -i`
- Скрипты читают ввод из `/dev/tty`, потому что stdin - сам скрипт (`curl | bash`). Неинтерактивный `ssh` - с `-n` или `</dev/null`
- Весь код в функциях, `main "$@"` - последняя строка: оборванная загрузка не выполнит половину скрипта
- `setup.ps1` работает в Windows PowerShell 5.1 и PowerShell 7, только ASCII. После каждого `ssh.exe`, `scp.exe` и `ssh-keygen.exe` проверять код выхода
- `*.sh` - только LF (`.gitattributes`)

## Проверки

Статические проверки (`requirements.md`, 11.3) - из корня репозитория, после любой правки скриптов. Все должны быть чистыми:

```
shellcheck setup.sh preflight.sh server.sh github.sh
/bin/bash -n setup.sh
LC_ALL=C grep -n '[^ -~	]' setup.ps1
pwsh -NoProfile -Command 'Invoke-ScriptAnalyzer -Path setup.ps1'
```

`grep` и `Invoke-ScriptAnalyzer` должны ничего не напечатать. `/bin/bash` на macOS - это bash 3.2; bash из brew эту проверку не заменяет.

Сценарии из `requirements.md`, 11.1, гонялись в Docker временным стендом, в репозитории его нет. Что проверено, а что осталось - `testing.md`.

## Запуск версии до релиза

Ссылки в README ведут на релиз - тег `v<версия>`. Чтобы запустить версию из конкретного коммита, подставьте его SHA в ссылку и передайте тот же адрес в `VPROD_BASE_URL`, иначе клиент скачает `preflight.sh` и `server.sh` из релиза. Ссылка - на SHA, не на ветку: у ветки raw.githubusercontent.com несколько минут отдаёт старый файл.

macOS и Linux:

```
B=https://raw.githubusercontent.com/ggender/vprod-env/<SHA>; curl -fsSL $B/setup.sh | VPROD_BASE_URL=$B bash
```

Windows:

```
$env:VPROD_BASE_URL='https://raw.githubusercontent.com/ggender/vprod-env/<SHA>'; [Net.ServicePointManager]::SecurityProtocol='Tls12'; iwr -useb "$env:VPROD_BASE_URL/setup.ps1" -OutFile "$env:TEMP\vprod-setup.ps1"; powershell -NoProfile -ExecutionPolicy Bypass -File "$env:TEMP\vprod-setup.ps1"
```

`github.sh` ничего не скачивает, ему `VPROD_BASE_URL` не нужен: `curl -fsSL https://raw.githubusercontent.com/ggender/vprod-env/<SHA>/github.sh | bash`.

## Версия и релиз

- Версия - строка `VPROD_ENV_VERSION=` во всех пяти скриптах, в `setup.ps1` ещё `$script:Version`
- Клиент отказывается от серверного скрипта другой версии. Поэтому версию меняют во всех файлах сразу и ставят тег `v<версия>` на этот коммит
- По умолчанию клиент берёт серверные скрипты из тега своей версии

## Агенту в этом режиме

- Коммит и push - только по просьбе пользователя. Если правку нужно проверить на сервере, а для этого нужен push, сказать об этом и спросить
- Требование неверное или неполное - не исправлять его молча. Сообщить пользователю и править `requirements.md` только после его решения
- Сервер для прогонов - рабочий сервер пользователя, вход `ssh vprod`, sudo без пароля. Адрес сервера в репозиторий не писать: репозиторий публичный
- На сервере делать только то, о чём просили. Вход в GitHub, в Claude и всё, где нужен код или браузер пользователя, запускает сам пользователь. Его процессы и сессии не останавливать
- Пароль root не спрашивать и не вводить: его вводит только пользователь, один раз, при первой установке

## Грабли, на которые уже наступали

- **bash 3.2 и ловушка ERR.** bash 3.2 запускает `trap ... ERR` внутри `$(...)` и конвейеров, даже если вызывающий код обрабатывает ошибку через `|| ...`. Поэтому `on_error` в `setup.sh` и `github.sh` сразу выходит при `BASH_SUBSHELL > 0`. Не убирать: на Linux ошибка не видна, она проявилась только при реальном запуске на Маке
- **Пробные входы по ключу** идут с `-o ControlMaster=no -o ControlPath=none` (`SSH_PROBE`, `$script:SshProbe`): если у ученика в config включён ControlMaster, `ssh` возьмёт уже открытое соединение и проба покажет неверный результат. Этого нет в требованиях, это добавлено при сборке
- **Красная плашка «noVNC encountered an error» с `chrome-extension://`** - ошибка расширения браузера, не сервера. Решение для ученика - в README
- **`gh` в тестах через expect** зависает: его вопросы ждут ответа терминала на запрос позиции курсора (`\033[6n`). В тестовом стенде надо отвечать на этот запрос, сам `github.sh` менять не нужно
- **Docker на Маке:** systemd в контейнере amd64 под эмуляцией не работает, на 26.04 под эмуляцией ломается `tar`. Гонять arm64-контейнеры с тестовыми заглушками (`preflight.sh` отказывает не-x86_64)
- **Ubuntu 26.04** использует uutils coreutils: новые флаги `coreutils` проверять и там
