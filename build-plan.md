# План сборки установщика

Один сервер, один чистый прогон, без переустановки ОС. Сборка на Маке, Windows - отдельным агентом в клоне репозитория.

## 0. До сборки

- Проверка требований агентом закончена, правки внесены
- Создан публичный репозиторий `ggender/vprod-env`, в нём `requirements.md`, `LICENSE`, `.gitattributes`
- Куплен сервер: Ubuntu 24.04, IPv4, есть IP и пароль root

## 1. Мак: сборка и статические проверки

- Новая сессия Claude Code в `~/dev/vprod/vprod-env`, не в `vprod`: та сессия видела код чужого установщика
- Модель Opus 5.5, усилие xhigh
- Без `/goal`: в середине работы шаг человека (ввод пароля root), до него агент сам не дойдёт
- Промпт:

```
Собери установщик удалённой среды строго по requirements.md в этом репозитории.

1. Прочитай requirements.md целиком. Сторонние установщики подобных сред не открывай и не используй как образец.
2. Составь план: файлы, функции, порядок шагов. Покажи мне план и дождись подтверждения.
3. Напиши setup.sh, setup.ps1, preflight.sh, server.sh и .gitattributes.
4. Прогони статические проверки из раздела 11.3, пока не станут чистыми. Недостающие инструменты (shellcheck, pwsh, PSScriptAnalyzer) поставь через brew и Install-Module.
5. Сделай коммит и пуш в main - это нужно, чтобы скрипты можно было скачать по ссылке на коммит.
6. Остановись и дай мне команду для запуска setup.sh с моего терминала:
   - VPROD_BASE_URL - ссылка raw.githubusercontent.com на SHA этого коммита, не на ветку: у ветки ссылка кэшируется на несколько минут
   - сервер: <IP>
```

## 2. Мак: первый прогон и отладка

- Вывод целиком - агенту
- Дальше агент работает сам: после установки у него есть вход `ssh vprod` и sudo без пароля, пароль root больше не нужен
- Промпт:

```
Я прогнал setup.sh, вывод ниже. Сервер <IP> - тестовый, на него можно заходить через ssh vprod и пользоваться sudo.

1. Разбери вывод. Если были ошибки - найди причину, исправь скрипты, коммит и пуш, повтори запуск через ssh vprod.
2. Проверь сценарии, которые можно пройти на этом сервере без переустановки: A5 (повторный запуск), check, desktop, login, проверки из 11.2.
3. Для каждой правки скажи, какой пункт требований она выполняет. Если требование неверное или неполное - не меняй его молча, а сообщи мне.
4. В конце - список: какие сценарии прошли, какие не проверялись и почему.

<вывод>
```

- Если сборка поломала доступ по SSH - заходить через VNC-консоль в панели ishosting

## 4. Windows: проверка `setup.ps1`

- Сервер уже настроен с Мака, а пароль root отключён. Чистый прогон с Windows на нём невозможен, поэтому Windows проверяется как второй компьютер с тем же ключом
- Подготовка:
  - Поставить Git, Claude Code и VS Code
  - Склонировать `ggender/vprod-env`
  - Скопировать с Мака `~/.ssh/vprod_ed25519` и `vprod_ed25519.pub` в `%USERPROFILE%\.ssh\`
- Сессия Claude Code в клоне, Opus 5.5, усилие high
- Промпт:

```
Проверь setup.ps1 на этой машине по requirements.md.

1. Прочитай requirements.md, разделы 3, 4, 8, 8.2, 9, 10 и 11.
2. Сервер <IP> уже настроен с другого компьютера, ключ ~/.ssh/vprod_ed25519 скопирован сюда. На сервер можно заходить и пользоваться sudo.
3. Запусти setup.ps1 в Windows PowerShell 5.1 (powershell.exe) с VPROD_BASE_URL на SHA последнего коммита. Ожидание - сценарий повторного запуска A5.
4. Повтори в PowerShell 7 (pwsh), если он установлен.
5. Проверь отдельно: создание ключа с пустой passphrase (запуск с VPROD_SSH_ALIAS=vprodtest; ожидание - ключ создан, затем остановка с сообщением, что сервер настроен с другого ключа), запись ~/.ssh/config, desktop, login.
6. Ошибки - исправь, коммит и пуш, повтори. Для каждой правки - какой пункт требований она выполняет. Если требование неверное - сообщи мне, не меняй молча.
7. В конце - список: что прошло, что не проверялось.
```

- После прогона руками: VS Code → Remote Explorer → `vprod` → Connect, `claude` в терминале VS Code работает без повторного входа

## pwsh

- `powershell.exe` - Windows PowerShell 5.1, встроен в Windows, развивается только исправлениями
- `pwsh` - PowerShell 7, отдельная кроссплатформенная версия: Windows, macOS, Linux. На Windows ставится рядом с 5.1, не заменяя его
- На Маке `pwsh` нужен только для проверок `setup.ps1` (PSScriptAnalyzer, разбор синтаксиса); поведение 5.1 на нём не проверить - это делается на Windows
