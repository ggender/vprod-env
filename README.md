# vprod-env

Установщик удалённой среды для курса [«Вайбкодинг»](https://vibecoding.main.guide/). Среда необязательная. Одна команда на вашем компьютере настраивает сервер Ubuntu с Claude Code и подключает к нему VS Code через Remote-SSH. Claude Code работает на мощном сервере, а не на вашем компьютере, а вы работаете в своём VS Code.

Неофициальный проект: он не связан с Anthropic и Microsoft. Claude и Claude Code - товарные знаки Anthropic, VS Code - товарный знак Microsoft.

## Установка

### Что нужно

- Сервер: новый виртуальный сервер (VPS) только под курс, не контейнер. Ubuntu 24.04, процессор x86_64 (Intel или AMD), IPv4-адрес и пароль root: их провайдер присылает в письме или показывает в панели. Память от 4 ГБ (на 2 ГБ установщик предупредит и спросит, продолжать ли), свободного места на диске - от 20 ГБ.
- Компьютер: macOS, Linux или Windows 10/11. VS Code лучше поставить заранее, иначе установщик подскажет, что сделать.
- Аккаунт Claude с доступом к Claude Code (платная подписка).
- Для раздела «GitHub на сервере» - аккаунт GitHub.

### Что изменится

На сервере:
- Появится пользователь `vprod` (имя можно выбрать) с правом sudo без пароля: так Claude Code сам ставит нужные программы. Значит, Claude Code может изменить на сервере что угодно.
- Вход под root и по паролю отключится: войти можно будет только по ключу с вашего компьютера.
- Включатся файрвол (снаружи открыт только SSH, прежние правила файрвола сбрасываются), защита от подбора паролей и автоматические обновления безопасности. Если памяти меньше 8 ГБ и подкачки нет, добавится файл подкачки на 2 ГБ.
- Установятся Claude Code и рабочий стол с Firefox. Рабочий стол открывается только через ваше SSH-подключение, снаружи его не видно.

Поэтому берите новый сервер только под курс, а не тот, где уже что-то работает.

На компьютере:
- Ключ `~/.ssh/vprod_ed25519` без пароля. Кто получит этот файл, тот войдёт на сервер: никому его не отправляйте. Если потеряете компьютер, потеряете и вход (см. «Если что-то пошло не так»).
- Подключение `vprod` в начале файла `~/.ssh/config`.
- Расширение Remote - SSH в VS Code, если VS Code уже установлен.

Проекты хранятся только на сервере, копии на компьютере нет. Чтобы не потерять код, регулярно делайте `git push` в GitHub.

### Как запустить

macOS и Linux - в обычном Терминале:

```
curl -fsSL https://raw.githubusercontent.com/ggender/vprod-env/v0.1.0/setup.sh | bash
```

Windows - в Windows PowerShell (PowerShell 7 пока не поддерживается):

```
[Net.ServicePointManager]::SecurityProtocol='Tls12'; iwr -useb https://raw.githubusercontent.com/ggender/vprod-env/v0.1.0/setup.ps1 -OutFile "$env:TEMP\vprod-setup.ps1"; powershell -NoProfile -ExecutionPolicy Bypass -File "$env:TEMP\vprod-setup.ps1"
```

### Что будет происходить

1. Установщик спросит адрес сервера, порт, имя пользователя и имя подключения. Enter оставляет значение по умолчанию: `22`, `vprod`, `vprod`.
2. Один раз попросит пароль root. Символы при вводе не видны, так и должно быть. Дальше вход только по ключу, пароль больше не нужен.
3. Сервер настраивается 5-10 минут. Если связь оборвётся, установщик переподключится сам. Если команда остановилась с ошибкой, запустите её ещё раз: она продолжит с того места, где остановилась.
4. В конце в браузере откроется рабочий стол сервера с окном Claude Code. Войдите в Claude там: страница входа откроется в Firefox на сервере. Не открывайте ссылку входа в своём браузере. Потом нажмите Enter в терминале.

### После установки

В VS Code:
1. Remote Explorer → `vprod` → Connect. Если спросит платформу - Linux.
2. Откройте папку `/home/vprod/projects` (если меняли имя пользователя - `/home/<имя>/projects`).
3. Terminal → New Terminal, запустите `claude`.

По желанию можно поставить расширение Claude Code на сервер: в расширениях найти Claude Code → `Install in SSH: vprod`.

## Другие команды

Та же команда установки с действием в конце: на macOS и Linux `bash -s -- <действие>` вместо `bash`, на Windows `-Action <действие>` в конце команды.

- `desktop` - открыть рабочий стол сервера снова
- `login` - войти в Claude заново
- `check` - проверить сервер

Например, на macOS и Linux:

```
curl -fsSL https://raw.githubusercontent.com/ggender/vprod-env/v0.1.0/setup.sh | bash -s -- check
```

На Windows:

```
[Net.ServicePointManager]::SecurityProtocol='Tls12'; iwr -useb https://raw.githubusercontent.com/ggender/vprod-env/v0.1.0/setup.ps1 -OutFile "$env:TEMP\vprod-setup.ps1"; powershell -NoProfile -ExecutionPolicy Bypass -File "$env:TEMP\vprod-setup.ps1" -Action check
```

## GitHub на сервере

Когда на сервере понадобятся свои репозитории, запустите в терминале VS Code, подключённом к серверу:

```
curl -fsSL https://raw.githubusercontent.com/ggender/vprod-env/v0.1.0/github.sh | bash
```

Скрипт поставит GitHub CLI и покажет код. Откройте https://github.com/login/device в любом браузере, хоть на своём компьютере, введите код и нажмите Authorize. Потом скрипт настроит `git` и спросит имя и почту для коммитов. После этого `gh repo clone`, `git pull` и `git push` работают без пароля.

Claude Code на сервере тоже сможет пользоваться этим доступом: читать и менять все ваши репозитории, включая приватные, и делать push. Убрать доступ с сервера: `gh auth logout`. Отозвать его совсем: https://github.com/settings/applications → GitHub CLI → Revoke access.

## Второй компьютер

Сервер пускает только по ключам, которые на нём записаны. Чтобы работать с сервером со второго компьютера, добавьте на сервер ключ этого компьютера. Приватный ключ между компьютерами не копируйте.

1. На втором компьютере запустите ту же команду установки, что и на первом, с теми же ответами (адрес сервера, порт, пользователь, имя подключения). Установщик создаст ключ и остановится с сообщением `This server is already set up with another key`. Так и должно быть: в сообщении будет путь к ключу этого компьютера.
2. На втором компьютере покажите публичный ключ. Его можно пересылать: это не секрет.
   - macOS и Linux: `cat ~/.ssh/vprod_ed25519.pub`
   - Windows (PowerShell): `Get-Content $env:USERPROFILE\.ssh\vprod_ed25519.pub`
3. На первом компьютере добавьте этот ключ на сервер, вставив строку ключа вместо `<ключ>`:
   ```
   echo '<ключ>' | ssh vprod 'cat >> ~/.ssh/authorized_keys'
   ```
4. На втором компьютере запустите команду установки ещё раз. Она войдёт по новому ключу, скажет `Everything is already set up.`, настроит подключение `vprod` и VS Code.

Если имя подключения не `vprod`, в путях и командах выше замените `vprod` на него. Чтобы отключить компьютер, удалите строку его ключа из `~/.ssh/authorized_keys` на сервере.

## Если что-то пошло не так

- **Команда остановилась с ошибкой.** Если в конце написано `Nothing is broken. Run the same command again to continue.` - запустите ту же команду ещё раз. Если ошибка после установки - запустите действие `check`, оно покажет, что не так.
- **`This server is already set up with another key`, а другого компьютера с доступом нет** (компьютер потерян, ключ удалён). Войти на сервер можно только через консоль в панели провайдера. Проще всего переустановить там Ubuntu и запустить установку заново. При переустановке всё на сервере удалится, поэтому и нужен `git push`.
- **Красная плашка «noVNC encountered an error»**, в тексте ошибки есть `chrome-extension://`. Ошибку выдаёт расширение браузера, а не сервер: noVNC показывает любую ошибку на странице. Не закрывайте терминал с установщиком и откройте ту же ссылку `http://127.0.0.1:…/vnc.html…` в другом браузере без расширений (Safari, Edge) или в окне инкогнито Chrome, где расширения выключены.

## Чего установщик не умеет

- Сервер без пароля root: провайдер выдаёт только ключ или пользователя `ubuntu`
- Сервер без IPv4, с процессором ARM, контейнер вместо обычного виртуального сервера
- Ubuntu, кроме 24.04. Ubuntu 26.04 пока не проверена
- PowerShell 7: пока не проверен, на Windows используйте Windows PowerShell
- Запуск в WSL: на Windows установка идёт только через Windows PowerShell
- Cursor и другие редакторы вместо VS Code
- Удаление среды: чтобы начать с нуля, переустановите Ubuntu в панели провайдера
- Node.js и стек проекта: их ставят по ходу курса
